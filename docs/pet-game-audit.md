# 동네 싸움왕 게임 점검

## 가장 큰 문제와 효과가 큰 개선

**가장 큰 문제 5개**

1. **서버가 상대와 승패를 충분히 검증하지 않는다.** 로컬 RPC 모형에서 존재하지 않는 Lv.999 상대의 1라운드 승리로 XP 28,944·코인 4,522를 받았다. 실제 DB에는 해당 요청을 보내지 않았다.
2. **승리와 보상 확정이 분리되어 있다.** 응답 유실·새로고침에서 정산 복구가 약하고, 승리 후 메인 코인이 늦게 갱신될 경로가 있다. 줍기는 실패해도 로컬 완료 표시가 남는다.
3. **공용 시트의 뒤로 가기 경합이 남아 있다.** 이전 시트의 늦은 `popstate`가 새 시트를 닫을 수 있다. 전투의 150ms 지연은 완전한 소유권 관리가 아니다.
4. **새 시작에서 첫 대결까지의 안내와 성장 연결이 약하다.** 시작 칸은 안전 구역이고 동물 지도는 기본 꺼짐이다. 서버의 스탯·직업·기술 성장과 실제 전투 구성도 연결이 덜 되어 있다.
5. **폰의 작은 조작부와 반복 연출·초기 코드 비용이 겹친다.** 360×640 전투의 정적 최소 높이는 676px이고 일부 조작부는 30~42px다. 홈 초기 스크립트는 합계 약 385KiB gzip이며 전투 이미지 경로에도 누락이 있다.

**가장 효과가 큰 개선 5개**

1. 서버에서 상대·보상 상한을 확정하고, 정산 요청 ID와 결과를 복구 가능하게 만든다.
2. 공용 시트와 전투가 하나의 전환 규칙으로 history·스크롤 잠금을 관리한다.
3. 첫 상대 찾기 → 첫 승리 → 확정 보상·다음 성장의 짧은 흐름을 만든다. 안내는 한 번에 한 줄만 보인다.
4. 타격·HP 감소·숫자·짧은 효과음을 같은 순간에 맞추고 반복 문구 시간을 줄인다. 이미 추가된 배속을 활용한다.
5. 작은 폰에서도 주요 버튼 44px와 명령 영역을 확보하고, 홈에서 전투 전용 데이터·그림을 필요한 시점에 불러온다.

## 점검 범위와 수치의 의미

2026-11-12 회사 PC의 로컬 작업 폴더를 점검했다. `AGENTS.md`, 모바일 기준, `docs/pet-king-design.md`, `docs/pet-roadmap.md`, `docs/pet-game-patterns*.md` 및 Next.js 16.2.1의 로컬 이미지·폰트·지연 로딩 가이드를 읽었다. 아래 파일·줄 번호는 점검 중 읽은 소스를 가리키며, 이후 편집에 따라 이동할 수 있다. 경로를 생략한 React 파일은 `app/games/`, 게임 라이브러리는 `lib/domine/` 아래다. `v14`, `v17`~`v20`은 `supabase/migrations/`의 해당 버전 SQL 파일을 뜻한다.

이번 작업에서는 소스와 SQL을 수정하지 않았고 Git 명령도 실행하지 않았다. 빌드는 허용된 1회만 실행했다. 다른 작업에서 01:10 이후 전투 배속·상태창·지원 기술·소모품과 v20 SQL을 추가하고 마지막 테스트 뒤에도 기대값을 수정하는 것을 관찰했다. 따라서 **빌드·시뮬레이션·테스트 결과는 각각 측정 시점의 결과**다. 상태창·소모품은 단순히 “없음”으로 판정하지 않았다. 실제 Supabase의 v20 적용 여부와 운영 데이터는 확인하지 않았다.

브라우저 도구는 agent-browser, BrowserOS neo 순으로 시도했으나 모두 자동 승인 정책에 막혔다. 아래 화면 크기와 터치 영역은 CSS 계산이며 실제 렌더링·스크린샷 판정이 아니다. 실제 폰의 LCP·INP·프레임률·힙 사용량도 미측정이다. 서버 변조 검증은 로컬 모형과 SQL 읽기로만 수행했다.

노력은 **S: 국소 변경**, **M: 한 기능과 관련 테스트**, **L: 클라이언트·서버 계약 또는 여러 상태 경로 변경**이다. 위험은 수정 시 회귀 위험, 효과는 사용자 경험·정확성·성능에 주는 효과다.

## 성장·보상·경제

### 레벨 공식과 승리만 가정한 성장량

`lib/domine/battle/rules.ts:19`의 누적 XP는 `6×(L−1)×(L+4)+floor(max(0,L−10)^3/25)`다. Lv.2는 36, Lv.10은 756, Lv.30은 6,236, Lv.60은 27,656이다. Lv.10→30에는 추가 5,480 XP가 필요하다.

v18 SQL:507~519의 기본 승리 XP는 `12+2×상대 레벨`, 기본 코인은 `2+floor(상대 레벨/5)`다. 상대 등급·레벨 차·첫 승리·연승이 곱해진다. 첫 승리 1.5배, 5연승 이상 XP 1.25배, 패배/무승부 XP 비율은 0.3/0.4다. 4레벨 이상 낮은 상대는 보상 제한을 받는다. 아래 계산은 **동급 일반 상대만 연속 승리**, 단계별 내림·초과 XP 이월을 적용했다.

| 조건 | Lv.1→10 | Lv.10→30 추가 | Lv.1→30 합계 |
|---|---:|---:|---:|
| 모두 해당 개체 첫 승리 | 19전 / 68코인 | 57전 / 462코인 | 76전 / 530코인 |
| 첫 승리 가산 없음 | 28전 / 73코인 | 85전 / 474코인 | 113전 / 547코인 |

이는 필요한 승리 수의 이상적 기준이며 실제 소요 시간이나 모든 사용자의 수입 예측은 아니다. 같은 개체는 승리 후 구간 내 퇴장하고 첫 승리도 공용 기록이므로 현실에서는 첫 승리만 계속 얻기 어렵다.

### 대결 길이를 포함한 성장 시뮬레이션

01:14 전후 엔진을 사용한 로컬 표본이다. 강아지별 12개 시드, 시작 구간 996000+시드×48, 난수 20261112+시드×97, 컨디션 70/70/80, 직업·수동 분배·소모품 없이 실행했다. 100칸에서 동급 주민 중 남은 상대를 고르고, 가능한 공격의 예상 피해×명중률이 가장 큰 기술을 선택했다. 기력이 부족하면 쉰다. 패한 상대를 다시 고를 수 있어 **무작정 재도전하는 경우의 스트레스 시나리오**다. 실제 이용자 평균이나 최적 전략의 승률이 아니다.

라운드마다 판단 2초, 대결마다 탐색·메뉴 10초를 추가했다. 실제 cue 길이에 기본 배속 1.7 및 3배 선택 시 5.1을 적용했다. 구간·퇴장 처리는 3배 시간축으로 진행했다. 따라서 기본 속도 열은 같은 전투 순서를 기본 속도로 재생할 때의 환산값이며 별도 기본 속도 플레이 시뮬레이션은 아니다.

| 강아지·구간 | 평균 대결 수 | 기본 속도 환산 | 3배 선택 | 30분 구간 대기 별도 | 획득 코인 |
|---|---:|---:|---:|---:|---:|
| 도미 1→10 | 79.8 | 96.9분 | 56.4분 | 4.6분 | 33.7 |
| 도미 10→30 | 250.0 | 278.4분 | 164.3분 | 12.9분 | 191.5 |
| 미네 1→10 | 63.1 | 78.2분 | 45.2분 | 12.3분 | 44.8 |
| 미네 10→30 | 259.8 | 259.4분 | 151.9분 | 19.3분 | 171.6 |

Lv.1→10 대결 수 범위는 도미 56~97, 미네 37~82였다. Lv.1→30 총합은 각각 평균 329.8전·322.9전이다. 이후 지원 기술·소모품 코드가 바뀌었으므로 이 표로 최신 밸런스를 확정하면 안 된다. 재측정 시 같은 시드·조건을 유지하고 순한 상대 우선 전략도 비교해야 한다.

- **현상:** 성장 시간을 XP 공식만 보고 판단하면 낙관적이다. 실패 반복과 긴 연출이 초반 체감 시간을 크게 늘릴 수 있다.
- **증거:** 이상적 19승과 위 스트레스 표본의 63~80전 사이에 차이가 크다. 변경 전 고정 600전 표본에서는 Lv.1 도미 승률 20%, 미네 69%, 평균 8.98/7.93라운드였다. 이 승률도 변경 전 진단값이다.
- **제안:** 먼저 첫 상대의 난도와 선택 안내를 조정하고 연출을 압축한다. 이후 동일 엔진 표본에서 첫 승리까지 시간과 Lv.10까지 시간을 다시 측정한다. XP 전체 배율 변경은 그 결과 뒤에 결정한다. 첫 승리 목표는 새 이용자가 5분 안에 경험하는 것으로 둔다.
- **노력 M · 위험 중 · 효과 높** / 파일: `PetEncounterSheet.tsx`, `pet-battle-view.ts`, `king/spawn.ts`, `scripts/pet-battle*.test.mjs`. 보상식 변경 시 SQL 별도.

### 소모품을 매번 쓰는 경제는 성립하기 어렵다

| 수입·지출 조건 | 계산값 |
|---|---:|
| Lv.1 / 10 / 30 일반 승리 코인 | 2 / 4 / 8 |
| 같은 레벨 해당 개체 첫 승리 코인 | 3 / 6 / 12 |
| 하루 30전·승률 60%·모두 첫 승리, Lv.1 / 10 / 30 | 54 / 108 / 216코인 |
| 새 칸 1회 줍기 기대값 | 0.12×(0.98×3+0.02×15) = 0.3888코인 |
| 30칸 / 100칸의 줍기 기대값 | 11.664 / 38.88코인 |
| 하루 15전×최저가 소모품 3개 | 540코인 |
| 하루 15전×회복 15·기력 12·강화 25 | 780코인 |

줍기는 공용 선점이므로 개인의 실제 수입은 이보다 낮을 수 있다. 주머니 발생은 칸당 0.24%다. 승리 드롭 5%라면 30승에 평균 1.5개이며 매 전투 사용량을 충당하지 못한다. 전직은 1차 무료·인증 조건, 2차 120코인, 3차 300코인과 인증이 필요하고 직업 변경에도 300코인이 든다. 두 강아지는 코인을 공유한다.

- **현상:** 외형 수집·전직과 상시 소모품 사용이 같은 지갑을 압박한다. Lv.30에서 하루 30번 모두 첫 승리하고 100칸을 혼자 주워도 약 398.9코인으로 최저 소모품 540코인에 못 미친다.
- **증거:** 설계서 경제 규칙, `battle/data.ts` 상품 가격, v18 보상식·줍기, v17 전직·드롭 로직. v20은 구매·예약·소모 정산을 추가하지만 수입 기반 자체는 바꾸지 않는다.
- **제안:** 소모품은 강적 대비 선택재로 명확히 안내한다. 매 대결 사용을 목표로 한다면 가격 또는 승리 드롭을 조정해야 한다. 기존 “대결 승리·맵 줍기로만 코인 획득” 원칙을 유지하고 돌봄·접속 보상으로 해결하지 않는다.
- **노력 M · 위험 중 · 효과 높** / 파일: `battle/data.ts`, `pet-king-items.ts`, `PetShopSheet.tsx`, 가격·드롭 SQL.

## 성능·최적화

### 빌드와 초기 스크립트

`npm run build` 1회 성공: 벽시계 **8.10초**, 컴파일 **2.7초**, TypeScript **3.2초**. `.next/BUILD_ID` 시각은 01:10:05다. middleware→proxy 사용 중단 예정 경고가 있었다. 이후 다른 작업의 소스 변경은 이 빌드에 포함되지 않는다.

### 공용 시트의 늦은 뒤로 가기 이벤트

- **현상:** 시트 A 닫기 → 시트 B 열기 직후 A의 history.back 이벤트가 도착하면 B가 닫힐 수 있다.
