**도미네 대결 모드 설계 초안**

대결 모드는 **동네를 산책하다 사람 NPC와 그 사람이 데리고 온 강아지 한 마리를 만나, 도미 또는 미네로 겨루는 1대1 턴제 놀이**로 만든다. 한 판은 6~10라운드, 60~120초를 목표로 한다.

견종은 수집 가능한 캐릭터가 아니라 **만나서 기록하는 상대**다. 플레이어가 사용하는 강아지는 골든 리트리버 도미와 말티즈 미네 두 마리로 고정한다. 공격은 달려들기·자리 차지하기·장난감 겨루기로 표현하고, HP는 화면에서 **버틸 힘**이라고 부른다. HP가 0이 되면 앉아서 쉬며 대결이 끝난다.

아래 수치와 승률은 구현 시작값과 검증 목표다. 실제 시뮬레이션으로 검증한 결과는 아니다. 견종별 그룹·기질·능력치는 외형과 활동 이미지를 활용한 **게임 설정**이며, 실제 견종의 성격이나 우열을 판정하는 자료로 사용하지 않는다.

**현재 구현과 연결하는 기준**

| 확인한 현재 구조 | 대결 모드의 연결 방식 |
|---|---|
| 게임은 메인 페이지의 `PetGame`에서 실행되고 `/games`는 메인으로 이동 | 기존 게임 안에 대결 진입 버튼을 추가한다. 별도 게임 페이지를 만들지 않는다. |
| 최신 펫 마이그레이션은 v9 | v11 대결 기능은 v10 완료 후 적용한다. v10의 실제 테이블 이름은 구현 시 확인한다. |
| 초기 설계서는 개인 경제지만, 최신 SQL은 공용 지갑·경험치·소지품 | 현재 SQL과 이번 요청을 기준으로 삼는다. 과거 개인 경제 설명을 재사용하지 않는다. |
| v10에서 레벨·소지품을 강아지별로 나눌 예정 | 대결 성장과 새 전투 소지품도 `pet_id=1 또는 2`로 구분한다. 소유자는 개인이 아니라 공동 강아지다. |
| 공용 코인은 현재 `domine_pet_v7.pool.coins` | 동일한 지갑을 사용한다. 전투 전용 코인을 만들지 않는다. |
| 행동 보상 2~6코인, 레벨 상승 보상 `10+2L` | 대결 승리 2~6코인, 전투 레벨 상승 코인은 0으로 정한다. |
| 풍경 정의는 24종, 실제 100칸에 사용된 풍경은 16종 | 24종의 NPC 풀을 정의하되, 없는 8종의 장소를 임의로 지도에 추가하지 않는다. |
| 기본 위치는 E5 용호성당 | 난이도 거리 계산의 기준점으로 사용한다. |
| 지도에서 원하는 칸으로 직접 이동 가능 | 이동 방식을 유지한다. 인접 칸 이동을 강제하지 않는다. |
| 기존 도감 ID는 `001~096`, 업적은 `A01~A30` | 견종 `B001~B072`, 기술 `T01~T72`, 아이템 `I01~I30`, 배지 `DB01~DB10`으로 분리한다. |
| 기존 요청 ID·재조회·응답 버전 구조가 있음 | 대결에도 적용하되 전투 턴 버전과 공용 지갑 버전을 분리한다. |

**전투 규칙**

| 항목 | 결정 |
|---|---|
| 참가 | 도미 또는 미네 한 마리 선택. 전투 중 교체 불가 |
| 상대 | 사람 NPC 한 명과 강아지 한 마리 |
| 기술 | 배운 기술 중 최대 4개 장착 |
| 기본 행동 | 장착 기술과 별도로 `가볍게 밀기`, `숨 고르기`, `가방`, `그만하기` 제공 |
| 자원 | 기력만 사용. 기술별 PP와 쿨다운은 도입하지 않음 |
| 기력 | 최대 10, 시작 6, 라운드 종료마다 2 회복 |
| 숨 고르기 | 기력 4 회복. 종료 회복까지 합쳐 최대 6 회복 |
| 아이템 | 한 판에 소모품 한 개만 반입·사용 가능 |
| 명령 제출 | 플레이어가 선택하면 서버가 양쪽 행동 한 라운드를 계산 |
| 상대 예고 | 상대가 사용할 다음 기술 또는 아이템을 이름까지 공개 |
| 승리 | 상대 HP가 0이 됨 |
| 최대 길이 | 12라운드 |
| 판정 | 12라운드 종료 시 남은 HP 비율 비교. 차이가 5%p 이하이면 무승부 |
| 패배 | 코인·기존 XP·공동 돌봄 수치 감소 없음. 이미 사용한 소모품만 소진 |
| 도망 | `그만하기` 성공률 100%. 보상 없음, 사용하지 않은 반입 소모품 반환 |
| 다음 대결 | 항상 HP·기력·상태를 초기화하고 시작 |
| 회복 제한 | 기술·특성·소모품으로 회복하는 HP 총량은 한 판에 최대 HP의 25% |
| 부활·치명타 | 없음 |

패배를 공동 강아지의 부상으로 연결하지 않는다. 다른 사람이 패배했다고 도미가 지치거나, 미네를 선택할 수 없게 되는 상황을 막기 위해서다.

`가볍게 밀기`는 중립 공격, 위력 12, 명중 95, 기력 0이다. `숨 고르기`는 자신 대상 보조 행동이며 반드시 성공한다. 두 행동은 모든 견종이 사용하며 아래 72개 기술 수에 포함하지 않는다.

**라운드 처리 순서**

1. 저장된 상대 명령과 플레이어 명령의 사용 가능 여부를 검사한다.
2. 라운드 시작 시점의 우선도·민첩으로 행동 순서를 확정한다.
3. 먼저 행동하는 쪽의 기력을 차감하고 명중·피해·부가 효과를 계산한다.
4. HP가 0인 강아지가 생기면 즉시 종료한다. 남은 행동은 실행하지 않는다.
5. 두 번째 행동을 같은 방법으로 처리한다.
6. 만료되는 효과를 제거하고 양쪽 기력을 2 회복한다.
7. 12라운드 판정과 승패를 확인한다.
8. 계속되는 전투라면 다음 상대 명령을 선택·저장하고 예고한다.

| 행동 | 우선도 |
|---|---:|
| 그만하기 | 3 |
| 소모품 | 2 |
| 방어 기술 | 1 |
| 기술 표에 `빠름`으로 표시한 공격 | 1 |
| 나머지 공격·보조·숨 고르기 | 0 |

같은 우선도에서는 민첩이 높은 쪽이 먼저 행동한다. 민첩도 같으면 서버 난수로 50%씩 결정한다. 해당 라운드 도중 발생한 민첩 변화는 다음 라운드부터 행동 순서에 반영한다.

기력은 **실제로 실행한 행동에만** 차감한다. 명중 실패에는 기력을 소비하고, 먼저 쓰러져 실행하지 못한 기술에는 소비하지 않는다.

**스탯과 성장**

스탯은 여섯 개다. 기력은 별도 공통 자원이며 일곱 번째 성장 스탯으로 취급하지 않는다.

| 표기 | 이름 | 역할 |
|---|---|---|
| H | 체력 | 최대 HP |
| A | 힘 | 돌진·기교·수호·지구 공격의 공격 수치 |
| D | 방어 | 접촉 공격과 추적 공격의 방어 수치 |
| V | 민첩 | 행동 순서와 상대 명중률에 영향 |
| F | 집중 | 추적·교감 공격, 명중률, 상태 부여 확률에 영향 |
| R | 침착 | 교감 공격 방어와 상태 저항에 영향 |

견종 표의 스탯 순서는 모두 **H/A/D/V/F/R**이다.

전투 레벨 `L`에서 장비를 제외한 스탯은 다음과 같다.

\[
q(L)=\min(L-1,19)+0.8\max(L-20,0)
\]

\[
S_i(L)=B_i+\lfloor g_iq(L)\rfloor
\]

- `B`는 견종별 레벨 1 기본 스탯이다.
- `g`는 아래 성장형의 증가량이다.
- 레벨 2~20은 증가량을 그대로 적용한다.
- 레벨 21~30은 증가량의 80%를 적용한다.
- 소수 증가분은 매 레벨 버리지 않고 누적 성장식의 마지막에서 내림한다.

| 성장형 | H | A | D | V | F | R | 용도 |
|---|---:|---:|---:|---:|---:|---:|---|
| G1 균형 | 4.0 | 1.0 | 0.9 | 0.9 | 0.9 | 0.8 | 폭넓은 기술 운용 |
| G2 민첩 | 3.2 | 0.8 | 0.7 | 1.3 | 1.1 | 0.8 | 빠른 순서·기교 |
| G3 방벽 | 4.8 | 1.1 | 1.3 | 0.5 | 0.6 | 0.8 | 방어·접촉 공격 |
| G4 탐색 | 3.6 | 0.8 | 0.8 | 1.0 | 1.4 | 0.6 | 추적·집중 공격 |
| G5 교감 | 3.2 | 0.6 | 0.7 | 1.0 | 1.2 | 1.2 | 교감 공격·상태 저항 |
| G6 지속 | 4.8 | 1.1 | 1.1 | 0.7 | 0.6 | 0.8 | 체력·장기전 |

성장형의 가중 증가량 `H/4+A+D+V+F+R`은 모두 5.5로 맞춘다. 특정 성장형이 전체 능력치 총량까지 독점하지 않게 하기 위해서다.

| 강아지 | 전투 Lv.1 | 전투 Lv.10 | 전투 Lv.30 |
|---|---|---|---|
| 도미 | 84/18/18/18/18/17 | 120/27/26/26/26/24 | 192/45/42/42/42/38 |
| 미네 | 68/13/14/23/24/19 | 96/20/20/34/33/26 | 154/34/32/58/53/40 |

**돌보기 레벨과 전투 레벨은 분리한다.** 기존 공동 성장의 의미를 유지하면서, 돌보기만으로 대결 전체를 즉시 끝내거나 대결로 기존 레벨업 코인을 반복 생산하는 문제를 피하기 위해서다.

| 항목 | 소유 범위 | 전투 영향 |
|---|---|---|
| 돌보기 레벨 1~30 | v10의 강아지별 공동 성장 | 직접적인 전투 스탯 보너스 없음 |
| 전투 레벨 1~30 | 강아지별 공동 성장 | 전투 스탯·기술 해금 |
| 공동 성장 단계 | 기존 돌봄 횟수 기준 | 외형에만 반영 |
| 배부름·기분·청결 | 기존 공동 수치 | 대결 참가·승률에 영향 없음 |
| 장착 기술 | 별명별·강아지별 | 다른 사람의 기술 구성을 덮어쓰지 않음 |
| 전투 장비 소유 | 강아지별 공동 | 소유 장비 중 자신의 출전 구성을 선택 |

전투 누적 XP는 다음 식으로 정한다.

\[

\]

\[
XP_{L\rightarrow L+1}=12L+24
\]

**상성은 기술·그룹·체급·기질을 나누어 적용한다**

견종은 게임상의 활동 그룹 하나, 기질 하나, 체급 하나를 가진다. 그룹은 실제 견종 분류 체계를 복제하지 않는다.

- **돌진:** 직선 이동과 추진력.
- **기교:** 작은 방향 전환과 자세 변화.
- **추적:** 냄새·시선·집중으로 빈틈 찾기.
- **수호:** 공간을 지키고 자세를 버티기.
- **교감:** 눈맞춤·소리·관심 끌기.
- **지구:** 호흡·보폭·반복 움직임.

공격자의 그룹 자체에는 추가 피해 보너스를 주지 않는다. **선택한 기술 속성과 상대 그룹**이 중요하도록 만든다.

| 공격 기술 ↓ / 상대 그룹 → | 돌진 | 기교 | 추적 | 수호 | 교감 | 지구 |
|---|---:|---:|---:|---:|---:|---:|
| 돌진 | 1.00 | 1.15 | 1.00 | 0.85 | 1.00 | 0.85 |
| 기교 | 1.00 | 1.00 | 0.85 | 1.15 | 0.85 | 1.15 |
| 추적 | 1.15 | 1.15 | 1.00 | 1.00 | 0.85 | 0.85 |
| 수호 | 1.15 | 0.85 | 1.00 | 1.00 | 1.15 | 1.00 |
| 교감 | 0.85 | 1.00 | 1.15 | 0.85 | 1.00 | 1.15 |
| 지구 | 1.00 | 0.85 | 1.15 | 1.15 | 1.00 | 1.00 |
| 중립 기본 행동 | 1.00 | 1.00 | 1.00 | 1.00 | 1.00 | 1.00 |

추적은 방향 전환을 따라잡고, 수호는 직선 접근을 받아내며, 기교는 굳힌 자세의 옆을 파고든다는 정도의 설명만 제공한다. 모든 관계를 외우게 하지 않는다.

체급은 **접촉 공격에만** 작은 보정을 준다. 작은 강아지가 큰 강아지에게 무조건 불리해지는 구조를 피한다.

| 공격자 ↓ / 방어자 → | 소형 | 중형 | 대형 |
|---|---:|---:|---:|
| 소형 | 1.00 | 1.03 | 1.05 |
| 중형 | 0.97 | 1.00 | 1.03 |
| 대형 | 0.95 | 0.97 | 1.00 |

추적·교감 공격은 체급 보정을 받지 않는다. 중립 기본 공격과 돌진·기교·수호·지구 공격은 접촉 공격이다.

기질은 피해량 대신 **상태 부여 확률**에만 영향을 준다. 아래 값은 확률의 퍼센트포인트 보정이다.

| 공격자 기질 ↓ / 상대 기질 → | 활발 | 신중 | 다정 | 꿋꿋 |
|---|---:|---:|---:|---:|
| 활발 | 0 | −5 | +5 | 0 |
| 신중 | +5 | 0 | 0 | −5 |
| 다정 | 0 | +5 | 0 | −5 |
| 꿋꿋 | −5 | 0 | +5 | 0 |

방어·회복·자신 대상 보조에는 위 세 표를 적용하지 않는다. 장소와 날씨도 전투 배율을 추가하지 않는다.

**명중·피해·상태 확률**

\[
명중률=\operatorname{clamp}(기술명중+0.3(F_a-V_d)+명중보정,\ 70,\ 99)
\]

- 숫자는 백분율이다.
- 소수 첫째 자리까지 계산하고, 서버에서 0~9,999 정수 난수와 비교한다.
- 자신 대상 행동은 명중 검사를 생략한다.
- `흐림`은 명중보정 −10이다.
- 별도의 회피 판정을 또 하지 않는다.

\[
피해=\max\left(1,\left\lfloor
\left[P(1+L_a/20)+0.45O\right]
\frac{40}{40+Q}
MZTGR
\right\rfloor\right)
\]

| 기호 | 뜻 |
|---|---|
| P | 기술 위력 |
| \(L_a\) | 공격자 전투 레벨 |
| O | 공격 수치. 추적·교감은 F, 나머지는 A |
| Q | 방어 수치. 교감은 R, 나머지는 D |
| M | 기술 속성 대 상대 그룹 배율 |
| Z | 접촉 공격 체급 배율. 비접촉은 1 |
| T | 특성·기술의 조건부 피해 보정 곱 |
| G | 방어막 배율. 없으면 1, 일반 방어막이면 0.65 |
| R | 피해 난수. 0.95·1.00·1.05 중 균등 선택 |

스탯 증감은 O와 Q를 계산할 때 반영한다. 같은 보너스를 T에도 다시 넣지 않는다. 피해 공식의 R은 계산식에서만 쓰는 난수 기호이며, 스탯 R인 침착과는 별도 값이다.

상태 부여 확률은 다음과 같다.

\[
상태확률=\operatorname{clamp}
(p_0+0.4(F_a-R_d)+기질보정,\ 10,\ 65)
\]

상태가 있는 공격은 **공격 명중 후** 상태 확률을 별도로 검사한다. 상대 대상 보조도 명중 후 같은 검사를 한다. `제거`와 `면역`은 상태 부여 확률을 거치지 않는다.

**피해 예시 세 개**

다음은 특성 미발동, 피해 난수 1.00인 경우다.

| 사례 | 계산 | 피해 |
|---|---|---:|
| 도미 Lv.10, T03 위력 20, 힘 27 → 방어 26, 교감 그룹·같은 체급 | `(20×1.5+0.45×27)×40/66×1×1` | 25 |
| 미네 Lv.10, T50 위력 18, 집중 33 → 침착 24, 추적 그룹 | `(18×1.5+0.45×33)×40/64×1.15` | 30 |
| 대형 Lv.10, T06 위력 24, 힘 27 → 방어 30, 소형 수호 그룹·방어막 | `(24×1.5+0.45×27)×40/70×0.85×0.95×0.65` | 14 |

세 번째 사례에서 상대가 최근 라운드에도 방어 기술을 사용했다면 연속 방어 규칙에 따라 G가 0.85가 되어 피해가 18로 증가한다.

**상태와 강화 효과**

| 상태 | 효과 | 지속 |
|---|---|---|
| 휘청 | 힘 −15% | 부여 라운드와 다음 라운드 |
| 흐림 | 명중률 −10%p | 동일 |
| 느림 | 민첩 −20% | 동일 |
| 긴장 | 집중 −20% | 동일 |
| 숨참 | 라운드 종료 기력 회복 2→1 | 동일 |
| 틈 | 방어 −15% | 동일 |

- 행동 불능, 수면, 지속 피해, 혼란 자해는 없다.
- 한 마리에게 서로 다른 상태 최대 2개.
- 세 번째 상태가 성공하면 가장 먼저 부여된 상태를 교체한다. 동시각이면 상태 ID 순서로 결정한다.
- 같은 상태는 강도를 중첩하지 않고 만료 라운드만 갱신한다.
- 만료 라운드 `r+1`의 상태는 해당 라운드 행동에 적용한 뒤 제거하고 기력을 회복한다. 따라서 숨참은 부여 라운드 종료 회복에 한 번 영향을 준다.
- `능력↑`는 해당 능력 +15%, 같은 능력끼리는 중첩하지 않고 기간만 갱신한다.
- 기본 강화 지속도 부여 라운드와 다음 라운드다.
- 강화와 약화가 동시에 있으면 배율을 곱하고 마지막에 내림한다.
- 방어막은 다음에 명중한 공격 한 번을 줄이고 사라진다. 빗나간 공격에는 소비되지 않는다.
- 방어막은 부여 라운드 다음 라운드 종료까지 유지한다.
- 직전 라운드에 방어 기술을 실행했다면 이번 방어 기술의 방어막은 0.65 대신 0.85다.
- 방어막끼리는 중첩하지 않는다. 새 방어막으로 교체한다.
- 기술 설명의 모든 회복은 남은 회복 한도와 실제 손실 HP 안에서 적용한다.

**아이템 30개**

\[
장비추가_i=
\begin{cases}
0 & 보너스가 없을 때\\
\max(1,\lfloor S_i\times 합산비율_i\rfloor) & 보너스가 있을 때

\]

NPC 장비는 상대 카드에서 모두 공개한다. NPC는 자신의 가상 소지품을 사용하고 공용 지갑이나 플레이어 재고에 접근하지 않는다. 플레이어에게 없는 숨은 능력치 장비는 만들지 않는다.

일반 NPC 장비의 세부 선택은 `날짜·칸·슬롯`을 입력으로 고정해 새로고침으로 바뀌지 않게 한다.

**100칸의 상대 배치**

E5 용호성당을 `(4,4)`로 놓는다. A1은 `(0,0)`, J10은 `(9,9)`다.

\[
d=|x-4|+|y-4|
\]

\[
지역등급=\min(5,\ 1+\lfloor d/2\rfloor)
\]

\[
일반상대레벨=\min(30,\ 1+2d+j)
\]

`j`는 해당 칸의 상대 슬롯 0·1·2다. 먼 칸일수록 강하지만 같은 거리에서 세 단계의 상대를 고를 수 있다.

| 성당 거리 | 지역 등급 | 기본 상대 레벨 범위 |
|---:|---:|---:|
| 0~1 | R1 | 1~5 |
| 2~3 | R2 | 5~9 |
| 4~5 | R3 | 9~13 |
| 6~7 | R4 | 13~17 |
| 8~10 | R5 | 17~23 |

모든 칸에 산책 상대 후보 세 명을 둔다. 장면에는 한 명만 표시하며 `다른 산책친구`로 나머지 후보를 순환한다. 이는 재추첨이 아니라 서버가 정한 세 슬롯 사이의 전환이다.

사람과 강아지는 한 쌍으로 등장한다. 사람 NPC는 직업이나 활동을 나타내는 가상 인물이며, 실제 장소의 직원·주민·성직자를 재현하지 않는다. 실재 가게에서는 점주로 단정하지 않고 `가게 앞에서 쉬는 이웃`처럼 표시한다.

**재도전과 조우**

- 상대를 만났다고 자동으로 전투를 시작하지 않는다.
- 상세 카드에서 사람·견종·레벨·장비·보상 가능 여부를 본 뒤 시작한다.
- 같은 NPC에는 종료 후 60초 뒤 재도전할 수 있다.
- 같은 날짜·같은 칸·같은 슬롯의 코인 보상은 별명당 한 번이다.
- 이미 이긴 상대와의 재대결도 가능하며 `연습 대결`로 표시한다.
- 연습 대결은 XP·코인 0이며 견종 완료 기록과 개인 배지 판정은 가능하다.
- 야생 강아지 전투와 포획은 넣지 않는다. 모든 대결 상대에게 함께 온 사람이 있다는 구성을 유지한다.
- 기존 도감의 동물 만남은 기존 탐색 콘텐츠로 남긴다.

**NPC 행동 선택**

상대는 플레이어의 이번 입력을 보고 기술을 바꾸지 않는다. 다음 라운드 명령을 이전 라운드 종료 시 확정해 저장한다.

일반 NPC는 아래 점수로 사용 가능한 행동을 평가한다.

| 조건 | 점수 |
|---|---:|
| 공격 | 예상 피해 ÷ 상대 최대 HP × 100 |
| 공격으로 상대 HP를 0으로 만들 수 있음 | 추가 40 |
| 자신의 HP가 40% 미만이고 회복 가능 | 회복 기술·아이템에 25 |
| 상대가 직전 라운드에 위력 22 이상 공격 사용 | 방어 기술에 15 |
| 해당 약화 상태가 있음 | 제거 기술에 제거 상태당 10 |
| 같은 능력 강화가 없음 | 강화 기술에 8 |
| 기력 2 이하 | 숨 고르기에 20 |
| 직전 라운드에 방어 사용 | 방어 기술에 −15 |
| 실제 효과 없는 회복·제거 | 후보 제외 |

예상 피해는 난수 1.00을 사용하고, 아직 제출되지 않은 플레이어 명령은 입력으로 사용하지 않는다.

- 일반 NPC: 상위 세 후보 중 60%·30%·10%로 선택.
- 고정 강자: 상위 두 후보 중 90%·10%.
- 후보가 부족하면 남은 후보끼리 확률을 정규화한다.
- 동점은 기술 ID 순으로 정렬한다.
- 기력이 부족한 기술, 이미 사용한 소모품, 회복 한도를 다 쓴 회복 기술은 제외한다.
- 다음 상대 명령의 이름·위력·우선도를 공개한다.

이 방식은 계산량이 작고, 상대 예고를 읽고 방어·빠른 공격·회복을 선택하는 플레이를 만든다.

**보상과 공동 경제**

보상은 전투 시작 시의 출전 레벨과 상대 정보를 기준으로 정한다. 다른 사람이 전투 도중 레벨을 올려도 그 판의 자격은 바뀌지 않는다.

| 결과 | 전투 XP | 공용 코인 |
|---|---:|---:|
| 일반 승리 | `10+2×지역등급` | `지역등급+1` |
| 고정 강자 승리 | 24 | 8 |
| 패배·무승부 | 2 | 0 |
| 도망·만료 | 0 | 0 |
| 연습 대결 | 0 | 0 |

상대 레벨이 출전 강아지보다 4 이상 낮으면 XP·코인 보상이 없는 연습 대결로 취급한다. 고정 강자의 최초 개인 승리는 이 낮은 상대 제한을 적용하지 않되, 아래 일일 상한은 적용한다.

| 제한 범위 | 한도 |
|---|---:|
| 별명별 코인 보상 승리 | 하루 6회 |
| 별명별 대결 코인 | 하루 24 |
| 공동체 전체 대결 코인 | 하루 180 |
| 별명별 전투 XP | 두 강아지 합산 하루 80 |
| 강아지별 공동 전투 XP | 하루 120 |
| 패배·무승부 XP | 별명별 하루 첫 3회 |
| 전투 레벨업 코인 | 0 |
| 견종 발견·배지 코인 | 0 |

실제 지급량은 기본 보상과 남은 한도 중 작은 값이다. 상한에 걸렸다고 승리 기록·배지·도감 등록을 막지 않는다. 보상을 시작 시 예약하지 않고 **종료 트랜잭션에서 확정**한다.

예를 들어 30명이 각각 6코인을 벌더라도 대결에서 공용 지갑으로 유입되는 코인은 하루 180이다. 30명이라는 이용자 수는 예시이며 실제 활동량을 측정한 값은 아니다. 이 상한은 별명 추가만으로 대결 코인을 무제한 발행하는 문제도 제한한다.

**여러 사람이 같은 강아지로 동시에 싸우는 경우**

전투는 공동 강아지의 능력치를 복사한 **독립 세션**이다.

| 데이터 | 처리 |
|---|---|
| HP·기력·상태·강화 | 전투별 보관. 공동 돌봄 상태에 쓰지 않음 |
| 출전 레벨·스탯·특성 | 시작 시 복사하여 종료까지 고정 |
| 다른 사람이 올린 전투 레벨 | 진행 중 판에는 미반영, 다음 판부터 반영 |
| 장비 | 시작 시 소유 확인 후 효과 복사 |
| 기술 구성 | 별명별 구성에서 복사 |
| 전투 XP | 종료 시 선택한 강아지에게 원자적으로 합산 |
| 코인 | 종료 시 공용 지갑에 원자적으로 합산 |
| 소모품 | 시작 시 한 개 예약, 사용 시 소진, 미사용이면 종료 시 반환 |
| 개인 견종 도감·배지 | 해당 전투를 진행한 별명에만 기록 |
| 한 별명의 중복 출전 | 동시에 활성 전투 한 개만 허용 |
| 서로 다른 별명 | 같은 도미로 동시 출전 가능 |

예를 들어 도미가 전투 Lv.8일 때 두 사람이 시작하고 먼저 끝난 사람이 Lv.9를 만들더라도, 나머지 전투는 Lv.8 스냅샷으로 계속된다. 나중에 끝난 사람의 XP는 현재 Lv.9의 누적 XP에 더한다. 예전 XP 값으로 덮어쓰지 않는다.

**서버가 매 라운드를 계산한다**

매 라운드 Supabase RPC가 양쪽 행동과 확률을 계산한다. 수십 명 규모에서는 요청량보다 조작 방지·재접속·보상 일관성이 더 중요하고, 한 라운드에 RPC 한 번이면 충분하기 때문이다.

클라이언트는 다음만 담당한다.

- 기술 선택과 입력 검증 안내.
- 서버가 준 피해 예상 범위·상성 힌트 표시.
- 확정된 이벤트의 SVG 연출.
- 요청 중·응답 불확실·재접속 화면.
- 이미지 로딩과 접근성.

서버는 다음을 전부 담당한다.

- 신원·전투 소유자·상대·학습 기술·장비 검증.
- 기력·우선도·명중·피해·상태·회복 한도 계산.
- 상대 행동 선택.
- 난수와 전투 버전 관리.
- 소모품 수량·보상·도감·배지 처리.

클라이언트는 피해량, 난수, 승리 여부, XP·코인 수치를 제출할 수 없다.

**v10과의 연결 계약**

v10이 아직 없으므로 존재하지 않는 테이블 이름을 전제로 SQL을 작성하지 않는다. v11 구현자는 다음 세 계약을 실제 v10 구조에 맞춘 내부 어댑터로 연결한다.

| 계약 | 요구 내용 |
|---|---|
| 공동 신원 | 기존 `player.id`와 기기 토큰 검증을 재사용 |
| 공용 지갑 | 기존 코인 행 하나를 잠그고 증감. 별도 v11 코인 잔액 금지 |
| 강아지별 소유 | 도미·미네의 돌보기 성장과 소지품을 읽을 수 있음 |

전투 XP와 새 전투 아이템은 v11 전용 테이블에 둔다. 기존 도감의 `001~096` 제약이나 `wearable/toy` 제약을 억지로 확장하지 않는다.

**중복 요청·난수·보상 트랜잭션**

- 전투 시작 시 32바이트 서버 비밀 난수 값을 생성한다.
- 라운드·행동자·명중·상태·피해·AI 선택마다 별도 라벨을 사용해 난수 스트림을 구분한다.
- 서버 비밀 값과 미래 난수는 응답하지 않는다.
- 실행 결과는 `turn`에 저장하며 재시도 시 재계산하지 않는다.
- `operation`의 같은 요청 ID와 같은 입력은 저장된 응답을 반환한다.
- 같은 요청 ID와 다른 입력은 `REQUEST_CONFLICT`다.
- 서로 다른 요청 ID로 같은 버전을 제출하면 첫 요청만 성공하고 나머지는 `STALE_VERSION`이다.
- 종료 라운드에서는 승패 저장·XP·코인·소모품·도감·배지를 한 트랜잭션으로 처리한다.
- 클라이언트가 별도의 `보상 받기` 명령을 보내는 구조는 만들지 않는다.
- `reward_ledger.battle_id`는 지급 재실행을 막는 최종 제약이다.

잠금 순서는 **기존 player → battle → 공용 지갑 → 공동 일일 한도 → 강아지 성장·일일 한도 → 아이템**으로 통일한다. 필요 없는 행은 잠그지 않는다. 중간 라운드에는 공용 지갑과 공동 성장 행을 잠그지 않는다.

기존 v10 경제 함수도 실제 잠금 순서를 확인해 같은 공유 행을 역순으로 잠그지 않게 맞춘다.

**요청 제한과 만료**

| 대상 | 제한 |
|---|---:|
| 별명별 대결 시작 | 분당 3회, 일 60회 |
| 별명별 턴 제출 | 분당 30회, 서로 다른 새 턴 최소 간격 1초 |
| 공동 턴 제출 | 분당 2,400회 |
| 별명별 상태 조회 | 분당 20회 |
| 별명별 로스터 조회 | 분당 30회 |
| 전투 유효 시간 | 마지막 유효 턴 후 10분 |
| 전투 최대 보관 활성 시간 | 시작 후 30분 |
| 요청·입력 크기 | 4KB 이하 |

기존 v6 경제 변경 제한 300회/분에 전투의 모든 턴을 넣지 않는다. 대결 전용 제한을 사용하고 실제 보상 정산 시에만 공용 경제 행을 갱신한다.

새 별명을 만들어 제한을 피할 수 있다는 한계는 남는다. 토큰을 로그인 계정과 동일한 신원 증명으로 취급하지 않고, 공용 코인·성장·소모품 지출의 공동 상한으로 피해 범위를 제한한다.

전투 만료는 상태 조회·새 전투 시작에서 지연 처리하고, 배치 정리도 같은 `expire_battle_v11`을 사용한다. 예약 소모품 반환은 상태를 `reserved→returned`로 한 번만 변경한다.

| 보조 행동 | 최소 44px | 기본 공격·숨 고르기·가방 |
| 로그 | 기본 한 줄 | 마지막 사건, 펼치면 전체 |

320px와 글자 확대 상태에서는 세로 스크롤을 허용한다. 1~2분 목표를 위해 중요한 행동을 손가락이 닿는 하단에 두되, 고정 영역이 장면과 내용을 가리지 않게 한다.

장면 배치는 다음을 기준으로 한다.

| 요소 | 논리 좌표·크기 |
|---|---|
| 우리 강아지 발 | `(45,82)` |
| 상대 강아지 발 | `(112,75)` |
| 사람 NPC 발 | `(137,69)` |
| 우리 강아지 최대 폭 | 34 |
| 상대 강아지 최대 폭 | 32 |
| 사람 NPC 최대 폭 | 16 |
| 공격 이동 | 원위치에서 최대 8 |
| 그림 보호 영역 | 외곽을 x=8~152, y=18~87 안에 유지 |

체급 차이는 소형 0.78, 중형 0.9, 대형 1.0의 화면 배율로만 표현한다. 대형견 사진 때문에 작은 강아지가 가려지지 않게 실제 길이 비율을 그대로 쓰지 않는다.

**기술 버튼에 표시할 내용**

```text
반가운 소리
기력 3 · 예상 28~31
유리 1.15배 · 명중 98%
```

상성 설명을 누르면 다음처럼 원인을 펼친다.

```text
교감 → 추적: 피해 +15%
체급 영향 없음
상대 방어막 없음
긴장 효과가 있어 내 집중 −20%
```

색만으로 유불리를 구분하지 않고 `유리 / 보통 / 불리`, 배율, 예상 피해를 함께 쓴다. 기질 보정은 상태 기술의 상세에서 `긴장 부여 예상 42%`처럼 보여 준다.

HP·기력·상태 설명은 HTML로 렌더링한다. SVG 안의 작은 글자에 핵심 정보를 의존하지 않는다.

**연출과 통신**

- 버튼 누름 반응은 50ms 안에 시작한다.
- 서버 응답 전에는 고개 들기 정도의 준비 동작만 한다.
- 피해·회복·승패는 서버 응답 뒤에 표시한다.
- 한 라운드 연출은 양쪽 합산 1.2~1.8초.
- 같은 행동의 타격 흔들기·숫자·말풍선은 단일 타임라인에서 처리한다.
- `prefers-reduced-motion`에서는 이동을 없애고 150ms 강조와 숫자로 대체한다.
- 소리는 넣지 않는다.
- 8초 동안 응답이 없으면 `결과 확인` 상태로 전환한다.
- 새 요청 ID를 만들지 않고 같은 요청을 재조회한다.
- 전투 시트 닫기는 대결 포기가 아니다. 메인에 `진행 중 대결 이어 하기`를 표시한다.
- `그만하기`만 서버에 포기를 제출한다.
- 다른 시트가 열렸거나 탭이 숨겨졌을 때 배경 장면 연출과 폴링을 멈춘다.

클라이언트 전투 상태는 `선택 가능 → 전송 중 → 결과 연출 → 선택 가능`으로 운영한다. `결과 불확실`, `종료`를 별도 상태로 두고 기존 돌보기의 명령 상태와 혼합하지 않는다.

**이미지 제작과 용량**

견종 이미지는 **Codex 이미지 생성으로 3×2 격자 시트를 만든 뒤 개별 강아지로 분리**한다. 한 셀에 한 견종, 한 자세만 넣는다. 전투 애니메이션은 기존 SVG 이동·회전·크기 변화로 처리한다.

그림은 실사 질감의 부드러운 컷아웃으로 통일하고, 도미·미네는 기존 자산을 참조해 게임 안의 모습과 이어지게 한다. 상대의 골든 리트리버·말티즈 그림은 각각 별도 견종 대표 이미지다.

| 자산 | 수량 | 제작 방식 | 배포 파일당 상한 | 합계 상한 |
|---|---:|---|---:|---:|
| 견종 전신 | 72 | 3×2 시트 12장 → 개별 컷 | 45KiB | 3,240KiB |
| 견종 도감 썸네일 | 72 | 전신에서 파생, 160px | 8KiB | 576KiB |
| 사람 NPC 기본형 | 24 | 3×2 시트 4장 | 25KiB | 600KiB |
| 아이템 아이콘 | 30 | 4×4 시트 2장 | 6KiB | 180KiB |
| 배지·상태·상성 기호 | 한 묶음 | 단순 SVG | 묶음 20KiB | 20KiB |
| 배경 | 신규 0 | 기존 풍경 재사용 | 추가 없음 | 0 |
| **전체** |  |  |  | **4,616KiB, 약 4.51MiB** |

원본 시트의 셀은 최소 640×640으로 확보한다. 큰 시트를 통째로 브라우저에 보내지 않는다.

**제작 규격**

- 같은 카메라 높이, 왼쪽을 보는 3/4 자세.
- 네 발과 꼬리가 셀 안에 들어오고 셀 가장자리 8%는 비운다.
- 셀 사이에 선·문자·숫자를 그리지 않는다.
- 투명 배경을 목표로 하되 결과의 알파·발 경계는 분리 후 확인한다.
- 사람은 실제 인물·브랜드 로고·상점 유니폼을 재현하지 않는다.
- 강아지의 화면 기준점은 발바닥 중앙으로 통일한다.
- 메타데이터에 `footAnchor`, `visibleBounds`, `scale`, `facing`을 저장한다.
- 원본 PNG·JPG와 격자 시트는 `public/`에 넣지 않는다.
- 분리한 전신은 `scripts/optimize_images.py --kind character`로 640px WebP 처리한다.
- 아이템은 `--kind item`, 썸네일은 `--kind item --width 160`으로 처리한다.
- 파일 상한 초과 시 품질을 낮추고, 그래도 초과하면 해당 이미지만 다시 제작한다.

초기 제작은 견종 12장·사람 4장·아이템 2장으로 **격자 생성 18회**, 재생성은 최대 9회로 작업량을 제한한다. 생성 비용은 현재 요금 추정치 대신 **전체 작업 상한 3만원**으로 잡고, 실제 생성 도구가 표시하는 비용으로 관리한다. 이 초안에서는 이미지를 생성하거나 비용을 사용하지 않는다.

**로딩 예산**

| 상황 | 추가 이미지 전송 목표 |
|---|---:|
| 기존 게임 첫 진입 | 대결 이미지 0 |
| 상대 상세 열기 | 상대 견종 45KiB + 사람 25KiB 이하 |
| 첫 전투 | 기존 도미·미네 자산 제외 신규 70KiB 이하 |
| 도감 첫 12칸 | 썸네일 96KiB 이하 |
| 대결 중 디코딩 이미지 메모리 | 12MiB 이하 |
| 대결 기능 JS | 지연 로드 gzip 45KiB 이하 |

이미지 실패 시 견종 이름이 붙은 공통 실루엣을 사용한다. 자산 오류로 진행 중 전투를 중단하지 않는다.

클라이언트 함수의 경계는 다음과 같이 잡는다.

```ts
declare function buildBattleStats(
  base: StatBlock,
  growth: StatBlock,
  level: number,
  equipmentRates: StatBlock
): StatBlock;

declare function getWorldDifficulty(
  cellId: string,
  slot: 0 | 1 | 2,
  advanced: boolean
): { distance: number; rank: number; level: number };

declare function previewAttack(
  attacker: BattleActor,
  defender: BattleActor,
  moveId: string,
  rulesetVersion: number
): {
  minDamage: number;
  maxDamage: number;
  hitChance: number;
  statusChance: number | null;
  hints: string[];
};

declare function acceptsBattleResponse(
  currentBattleId: string | null,
  currentVersion: number,
  response: BattleResponse
): boolean;

declare function battleLevelFromXp(xp: number): number;

declare function battleXpAtLevel(level: number): number;
```

成長値用の `StatBlock.hp`は HP 증가량、장비 비율용 `StatBlock.hp`는 체력 증가 비율로 사용한다. 구현에서는 같은 타입을 서로 혼동하지 않도록 `GrowthBlock`, `EquipmentRateBlock` 별칭을 붙인다.

피해 예상은 안내용이다. 서버 결과와 불일치해도 클라이언트 계산으로 HP를 수정하지 않는다. 서버와 클라이언트의 계산 차이는 계약 테스트에서 검출한다.

1단계부터 핵심 상성·기력·정산 공식을 완성한다. 이후 단계에서 기존 전투 규칙을 갈아엎지 않고 콘텐츠와 표시 기능을 늘린다.

SQL은 사용자가 붙여 실행한다. 배포 순서는 **기능 감지 가능한 클라이언트 → v11 SQL 적용 → capabilities 확인 → 기능 활성화**로 정한다. SQL 적용 전에는 대결 버튼을 준비 상태로 표시하며 기존 돌보기 RPC를 전투 대체 경로로 호출하지 않는다.

각 실제 코드 단계는 해당 테스트, lint·build, 모바일 확인 후 프로젝트 규칙에 따라 배포 인덱스를 1 올리고 커밋·푸시한다. 이 독립 설계 초안에서는 파일·배포 인덱스·Git을 변경하지 않는다.

**시뮬레이션 방법**

시뮬레이션은 UI를 거치지 않고 서버의 순수 계산 함수를 호출한다. 실제 운영 난수 대신 고정 시드 목록을 사용한다.

먼저 도미·미네 × 대표 상대 12종 × 레벨 1·10·20·30 × 시드 20개로 **1,920판**을 실행해 규칙 오류와 지나친 회복·방어 반복을 찾는다. 이 검증을 통과한 뒤 전체 밸런스를 한 번 계산한다.

전체 검증은 도미·미네 × 상대 72종 × 레벨 1·10·20·30 × 시드 200개로 **115,200판**이다. 플레이어 역할의 정책은 상대 예고를 읽고 두 라운드 기대 결과를 평가하는 동일한 정책을 사용한다. 견종마다 유리한 별도 AI를 수작업으로 붙이지 않는다.

최종 표에는 표본 수·승률·무승부율·평균 라운드·회복량·선공률·기술 사용률을 함께 기록한다. 무승부는 승률에서 0.5승으로 처리한 값과 순수 승리 비율을 둘 다 저장한다.

수치를 바꿀 때는 다음 순서로 조정한다.

1. 모든 판이 너무 길거나 짧으면 공통 피해 계수와 회복 한도를 조정한다.
2. 도미·미네의 전체 승률 차이는 두 견종의 스탯 배분·기술 구성으로 조정한다.
3. 특정 그룹만 치우치면 해당 상성표 한 칸이나 기술 위력을 조정한다.
4. 마지막으로 개별 특성을 조정한다.

여러 계층을 동시에 바꾸면 원인을 알 수 없으므로 한 번에 한 계층만 변경한다. 합격 기준을 통과하면 추가 반복 튜닝을 멈춘다.

**모바일 검증**

- 320·360·390·430px 폭에서 기술명·기력·상성 힌트가 잘리지 않는다.

- 대결이 끝나면 기존 돌보기·지도 이동의 입력 잠금이 해제된다.
